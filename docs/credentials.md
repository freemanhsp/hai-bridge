# 凭据与设备信任

## 当前0.5.0是什么

| 内容 | 留在哪里 | 程序包是否带入 |
| --- | --- | --- |
| HAI/SSO认证、A明确的auth.json | 只在A，公司认证由HAI维护 | 不带入 |
| A→ECS SSH私钥、B→ECS SSH私钥 | 分别在各自设备，交给本机OpenSSH使用 | 普通包和私有应用配对包都不带入 |
| A TLS私钥 | A私有配对目录 | 不交付B |
| B TLS私钥/证书、CA公开证书与A信任元数据 | B私有配对目录 | 旧私有试用包带入；普通runtime.tgz不带入 |
| 独立随机bridge token、模型名 | 真实配对的access.json，A/B各持一份 | 旧真实私有试用包带入；普通包不带入 |

此前Windows真实报告来自私有试用包的导入流程，因此B已加载那一份应用身份；这不证明用户执行过0.5.0的setup-client，也不是把HAI账号文件交给B。不要公开上传完整试用包或client.json.tls。

setup-client只私下复制已有B身份并保存连接配置；SSH身份/known_hosts仍引用原路径。setup-publisher只记住A配置路径。安装/升级、移动普通包、复制配对均不会重新签发或续期。

## 期限与现有限制

CA、A证书、B证书均从生成时起约7天有效，最早失效的一环会阻止连接；A/B整证书指纹固定。CA签名私钥生成后销毁，不能对旧身份直接滚动补签。bridge token自身没有expiry字段，但不能独立越过TLS身份和SSH访问约束。

当前A只允许一个固定B证书身份，没有“信任设备列表”、逐设备授权/撤销、自动续期或过期恢复。复制同一B私钥到Windows/WSL/另一台Mac只是克隆同一身份，不代表安全登记了不同设备。普通文件私钥证明持有密钥，不证明物理硬件。

过期需新私有配对与显式配置切换；选择新目录以保留旧资产，不覆盖默认项、不关闭证书/名称/指纹校验。初始化不会自动给新设备配置ECS公钥或公司授权。HAI自身登录、额度/模型权限失败也不会被桥接配对续期解决。

## 推荐的后续机制（未实现）

先让B在本机产生长期身份私钥，仅以文件交换登记公钥/持有证明；A明确批准、公钥指纹登记、列表与撤销。Windows/WSL/其他Mac默认独立身份，新增设备仍须在用户与HAI团队对齐范围内。

推荐设备授权维持至撤销、连接证书短期滚动更新，不发永久证书。新版本schema显式迁移：A保存受保护的签发能力及稳定公开信任锚，依据已批准设备签发；A/B叶证书和信任锚轮换都要考虑，撤销须阻止新请求与续期。

先做有效期内续期与原子配置切换；失败不能损坏仍有效旧配置、不重放模型POST。已过期mTLS不能直接访问原续期路由；第一阶段可明确要求人工恢复，完整无人值守恢复需窄控制面、受信长期密钥挑战签名、防重放/限速/撤销检查，不能让控制面直接调用模型。

A离线/休眠、系统时间错误、签发密钥丢失或信任锚失效时不能保证无限无人值守恢复。硬件密钥库、GUI、多用户审批平台后评估。本轮只整理机制，没有延长期限或替换任何凭据；近期先做[生命周期与到期诊断](next-development.md)。
