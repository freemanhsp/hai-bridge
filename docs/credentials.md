# 凭据与设备信任

2026-11-25：0.5.1保留独立app-device v2与旧app-tls v1。用户已单独登记真实v2设备并实战成功，不是自动迁移旧v1身份。下面的短期客户端证书说明仅针对v1；已有v2按[程序升级](windows-upgrade.md)复用原配置/密钥，不重新登记。

## 已有0.5.0 / v1配对是什么

| 内容 | 留在哪里 | 程序包是否带入 |
| --- | --- | --- |
| HAI/SSO认证、A明确的auth.json | 只在A，公司认证由HAI维护 | 不带入 |
| A→ECS SSH私钥、B→ECS SSH私钥 | 分别在各自设备，交给本机OpenSSH使用 | 普通包和私有应用配对包都不带入 |
| A TLS私钥 | A私有配对目录 | 不交付B |
| B TLS私钥/证书、CA公开证书与A信任元数据 | B私有配对目录 | 旧私有试用包带入；普通runtime.tgz不带入 |
| 独立随机bridge token、模型名 | 真实配对的access.json，A/B各持一份 | 旧真实私有试用包带入；普通包不带入 |

此前Windows真实报告来自私有试用包的导入流程，因此B已加载那一份应用身份；这不证明用户执行过0.5.0的setup-client，也不是把HAI账号文件交给B。不要公开上传完整试用包或client.json.tls。

setup-client只私下复制已有B身份并保存连接配置；SSH身份/known_hosts仍引用原路径。setup-publisher只记住A配置路径。安装/升级、移动普通包、复制配对均不会重新签发或续期。

## 期限与现有限制

CA、A证书、B证书均从生成时起约7天有效，最早失效的一环会阻止连接；A/B整证书指纹固定。CA签名私钥生成后销毁，不能对旧身份直接滚动补签。bridge token自身没有expiry字段，但不能独立越过TLS身份和SSH访问约束。

v1 A只允许一个固定B证书身份，没有“信任设备列表”、逐设备授权/撤销、自动续期或过期恢复。复制同一B私钥到Windows/WSL/另一台Mac只是克隆同一身份，不代表安全登记了不同设备。普通文件私钥证明持有密钥，不证明物理硬件。

过期需新私有配对与显式配置切换；选择新目录以保留旧资产，不覆盖默认项、不关闭证书/名称/指纹校验。初始化不会自动给新设备配置ECS公钥或公司授权。HAI自身登录、额度/模型权限失败也不会被桥接配对续期解决。

## 个人版 v2（已实现，用户已登记真实 B）

B 本机生成一把 Ed25519 长期设备私钥；通过 A 私密短期邀请登记公钥/签名，A核对完整指纹后批准。Windows/WSL/其他Mac分别登记，不共享私钥。A保留pending/approved/revoked和授权代次；撤销阻止新请求、旧会话和后续认证，活动流有界轮询取消。

不采用旧草稿“双B密钥 + B客户端证书续签”。v2 TLS仅认证A，B签随机挑战取得最长10分钟的内存会话，后续请求前自动刷新；B没有TLS客户端证书，因此没有B证书过期恢复问题。设备授权持续至撤销，不保证物理设备不可克隆或永不需要维护。

A保留独立应用CA签发私钥与稳定服务器公钥；叶证书约7天，在48小时临期时启动/定时原子续订。B固定CA、服务器名与SPKI，不固定整张叶证书，所以正常续订无需再传文件。根约一年，到期/换根仍需显式信任重建；不能由联网控制面静默替换。密钥与注册表必须保护，不恢复可能撤销前的旧状态快照。

A离线/休眠、系统时间错误、根失效、A/B长期密钥丢失或已撤销时仍需人工处理。A重启清空会话，B可能收到一次401再自动认证后续新请求；不重放已失败模型POST。普通包不带入身份，v2邀请不带入任何私钥或HAI认证；旧私有试用包不能替代新登记。

当前整理/提交/打包不替换个人凭据，不启动真实HAI/ECS或续签旧配对。用户已提供真实v2工具任务成功反馈；新包入口、Windows ACL、真实撤销/叶续签、其他平台和长期稳定性另行验收。use-client只保存原配置路径，原client.json/device目录仍需保留；inspect-app仅诊断v1。GUI、系统密钥库、根轮换向导、多人权限/额度和完整监控未实现。
