- A/B 保持已有出站 ECS SSH 与应用 TLS，v1为mTLS、v2为服务器TLS+设备签名；不在 ECS 部署明文代理，不新增公网应用入口。
- 本次用户确认范围是个人 Windows→个人 ECS→公司 Mac；扩展设备/用户/用途或网络路径前另确认。
- 模型 POST 不自动重放；本地通过、用户报告、设计与未验证项分别记录。
- mydocs 保留草稿，docs 为正式说明，explore 为历史证据；不强加 GitHub issue/项目管理方式。

## 凭据到期与长期信任

现有v1 CA/A/B证书约7天，CA签名密钥已销毁，不能原地续签。需要显式新目录/身份切换，不覆盖旧配置；inspect-app仅诊断v1。本轮没有续签现有个人身份。

已实施的简化v2是“设备授权持续至撤销 + 挑战签名/自动短会话”，B无客户端证书。A持有独立CA和稳定服务器公钥，续订7天叶证书；约一年根仍需显式配对，密钥丢失/撤销不能自动恢复。详情见[凭据说明](credentials.md)与[个人设备操作](device-auth.md)。

## 可以停止或暂缓

- 停止重复零散models/SSE/取消/429/503基础检查；已有回归和报告保留。
- 停止旧 Mac 系统登录链路、内层SSH权限改造与其新验收；历史资产不删除。
- 暂不做GUI、后台守护、自启动、WSS重写、打洞、多中继和多用户管理平台。
- 不采用永久证书、复制B私钥实现“设备信任”，不忽略过期/名称/指纹校验。
- 不默认采集提示词/回复或原始headers/stderr；不做全文抓包、请求缓存、自动计费POST重试。

## 另需授权的运维与真实验证

专用publisher账号的ECS服务端ClientAlive策略可单独评估。须先由获准管理员核查有效配置/Match上下文，验证兼容性、保持管理通道、备份并可回滚；不盲目重启整个sshd或自动更改全局参数。心跳不是父进程强杀保护，不能承诺固定秒数或所有故障清零。

安全组可能共享，root/密码登录与账号授权也属独立运维范围；计划不意味着已获修改授权。真实AI工具任务会发送项目内容并计费，先说明再执行。跨设备窗口先校验版本/commit/包哈希、身份期限和独占mock计数，再批量验收；Windows、WSL和Mac-B分别报告。

历史阶段与实测保留在[验证记录](validation.md)和[探索索引](../explore/README.md)。未推送的提交不能由B直接从GitHub拉取；也可私下交付经校验的普通程序包，配对独立保密传输。
