## 下一轮验收组织

为减少 Windows/Mac 切换，先准备同版本代码和配置，再安排集中窗口。历史 windows-checks.ps1 保持为协议回归资产，人工重启不能证明自动恢复。0.2.0 已实现 Windows/WSL 共用的 B 端 check-lifecycle，见 [集中检查](lifecycle-checks.md)；内层故障注入由命令结束自己的SSH子进程，不需手工查PID或重启。Mac外层协同及真实跨设备结果仍待后续，阶段2不提前标绿。

1. 记录旧隧道/配置，停止旧专用 SSH 后用 CLI 迁移；不杀其他监听。先证明两端启动和 `doctor` 成功。
2. 在 B 中断测试内层 SSH 子进程但保留 CLI，观察有限重建；验证在途流失败、上游活动流归零、旧请求未重放、新请求成功。Ctrl-C 停掉整个 CLI 只能验证主动停止，不能验证自动恢复。
3. 在 Mac 中断测试外层 SSH 子进程但保留 publisher，观察 publisher 与 B 各自恢复；同样检查在途清理与新请求。故障注入必须识别本轮专属进程，不碰 VPN 或其他 SSH。
4. 集中验证端口冲突、信任缺失/变化、认证失败停止；使用独立临时配置，不覆盖正常信任文件。两端 Ctrl-C 后确认自有端口释放且其他服务不受影响。
5. WSL 独立重复启动、流式与停止/恢复检查，使用自己的密钥、信任文件和本地端口；将 Windows 与 WSL 结果分别标注。

只注入 SSH 进程中断不等于真实断网、VPN 重连或 Mac 休眠已经验证；后者留到长期使用阶段。

## 权限收紧的重点

当前 Mac 公钥上的 `permitopen` 只限制本地/直连目标，不等于禁止反向转发。需评估 `Match` 级 `AllowTcpForwarding` 方向限制与 ECS 的 `PermitListen`/`PermitOpen`，不能只凭现有 key 选项宣称完整隔离。

安全组可能共享；先确认关联实例，不能直接删除历史规则。root/密码登录调整必须先验证替代管理通道，并获得明确授权。本阶段计划不代表已经修改上述设置。
